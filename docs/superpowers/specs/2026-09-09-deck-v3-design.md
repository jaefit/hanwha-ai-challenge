# 피치 덱 v3 — 파이프라인 순서 11장 설계

작성 2026-09-09 · 대면 5분 + 질의 발표용 `docs/deck.html` 재구조 설계. 결정 주체는 사용자, 이 문서는 그 결정의 기록이다.

## 1. 왜 다시 짜나

- 9/9 오전 덱을 Claude Design 「Pitch Deck v2」 원안 12장으로 되돌렸다(`7fd2a95`). 사용자 판정: **글이 너무 많고, 이야기 흐름이 약하다.** 비주얼(토스풍 라이트·오렌지·다크 훅/클로징)은 불만 아님.
- 심사위원이 기억할 한 줄(사용자): **"설계 → 예측 → 검증까지 했고, 후속 플랜까지 있다. 현실화 가능하다."**
- 구조는 사용자가 정했다: **우리 시스템의 파이프라인 순서 그대로.** 문제 → 왜 예측과 실측이 둘 다 필요한가 → 예측 방법 → 실측 API → 실측 처리 → 실제 데이터 재현 → 예측 vs 실측 → 다음 스텝 → 끝.
- **부록 없음**(사용자). 검증 장·AI 활용 장·코드 스트립도 없음 — 검증 건수는 다음 스텝 장의 노트에, AI 활용은 편집기·보고서에 이미 있다.

## 2. 장 규칙

1. 한 장 = **헤드라인 1문장 + 시각 요소 1 + 보조 문장 ≤2줄.** 회색 각주 문단은 전부 삭제하고 발표자 노트로 옮긴다.
2. 손 숫자 금지 원칙 유지 — 본문 숫자는 `docs/deck/*.json` 과 `tests/test_deck.py` 가 대조한다. 새 데이터 파일은 만들지 않는다.
3. 비주얼 토큰은 v2 그대로(1920×1080 `deck-stage`, Pretendard, `#F36F21`, 카드 `#F2F4F6` r28, 다크 `#17171C`). 새 차트 함수 0 — `docs/app/deck_charts.js` 의 기존 함수만 쓴다.
4. 발표자 노트 60~170자 유지(장당 25초).
