서울세계불꽃축제 귀가 출구 내비 — 진행 보고

2026-08-31 기준 · 작성: 박재형 · 대시보드 · 저장소 · 행사일 9/5(토) · 제출 9/8(화) 20:00

1문제 제기 — 귀가가 무너진다

축제 당일 여의도에 약 100만 명이 모이고, 불꽃쇼가 끝나는 순간 전원이 동시에 귀가를 시작한다. 문제는 혼잡 자체가 아니라 기존 도구가 당일 통제를 모른다는 것이다.

  • 지도앱은 여의나루역으로 안내한다. 그러나 여의나루역은 축제일 저녁 무정차 통제된다 — 2024·2025 실적: 19~21시 하차 인원 ≈ 0 (서울교통공사 OA-12921). 기사 예상이 아니라 데이터.
  • 여의도역 승차는 21시에 평시 토요일의 12~17배로 튄다 (2024·2025). 어느 역이 언제 몰리는지는 시간대별로 완전히 다르다.
  • 서울시 실시간 도시데이터는 "붐빔"이라는 상태만 준다. 관람객에게 필요한 것은 행동 — 어디로, 언제 나갈지 — 인데 이를 주는 서비스가 없다.
  • 대상: 관람객. KT 생활이동 기준 20·30대 여성이 최다 집단.

2해결 방안 — 상태가 아니라 행동을 준다

"지금 어디로 나가야 덜 막히나"를 3초 안에 읽는 웹페이지. 출구 7개 × 시간대(19~23시)별 부하율을 예측해 등급·대기시간·순위로 보여준다.

  • 출구 7개: 여의도(5) · 여의나루(5) · 신길(1·5) · 여의도(9) · 샛강(9) · 국회의사당(9) · 마포역 도보(마포대교)
  • 등급 4단계: 여유 <0.5 주의 0.5~0.8 경계 0.8~1.0 심각 ≥1.0 (부하율 = 수요 ÷ 처리용량)
  • 통제 반영: 여의나루 임시 통제 20:40~21:40 (2026 공식 공지) — 해당 시간대 "무정차" 행으로 표시
  • 정적 GitHub Pages — 라이브 데이터가 죽어도 사전 예측표로 자동 폴백, 통신 폭주 대비 localStorage 캐시
  • 예정: 질의형 챗봇 프롬프트("애오개 가려면?"), 오프라인 플랜 카드

3설계 방법 — 관측에 앵커한 구조 모델

3.1 왜 머신러닝이 아닌가

학습 표본이 축제일 2일(2024·2025)뿐이다. 소표본에 모델을 학습시키는 대신, 실측을 앵커로 쓰는 구조 모델을 짰다. 애틀랜타 MARTA 사례(경기장 이벤트 수요, 선형회귀+정규화 곡선, MAPE 11.7%)와 같은 계열의 접근.

3.2 수요 식 — 3개 요소의 곱

출구 수요(역, 시각) = α × Est × 도착형태(시각)
요소내용근거 데이터
Est 규모·분배축제일 초과 승차 = 축제일 승차 − 평시 토요일 중앙값. 2년 평균 총 10.9만 명, 비중: 여의도(5) 29% · 샛강 17% · 여의도(9) 17% · 마포도보 13% · 국회 11% · 여의나루 10% · 신길 3%서울교통공사 시간대별(OA-12921), 교통카드 일별(OA-12914)
도착형태 시간 분포KT 생활이동 유출 곡선 → 쇼 종료 앵커 +40분 이동(2026 21:10 종료) → 구역→출구 거리 ÷ 밀도별 보행속도(Kladek/Weidmann 식)로 도달 지연KT OD 2일, 공지 시간표
α 당일 규모 배율당일 관측으로 갱신되는 사후분포 (3.3)서울 실시간 도시데이터
  • 처리용량 = 역별 관측 최대 시간당 승차. 9호선 3역·신길 1호선은 교통카드 일승차 비례 추정(추정 표기).
  • 통제 규칙: 여의나루 20~21시 수요 0. 통제 중 도착분은 해제 후 첫 개방 시간대(22시)로 이월 — 실측 근거: 해제 직후 승차 2024년 2.3천 / 2025년 5.8천 명.

3.3 당일 보정 — α 격자 데이터동화

  • α를 점추정이 아니라 격자 61점 사후분포(베이즈 갱신)로 유지. 사전 = 2년 관측 변동폭.
  • 관측 2종: O1 여의나루 30분 하차 증분(도착측, 12~19시) · O2 여의도 핫스팟 9역 30분 승차(귀가측, 19시~). 5분 주기.
  • 예측 밴드 = 사후분포 p10~p90. 관측이 쌓이면 밴드가 좁아지고, 관측이 없으면 사전 예측표와 동일.

3.4 검증 — 백테스트

2024·2025 축제일 실측(시간대 승차 4역)으로 모델을 되돌려 검증. B가 2026이 실제로 놓이는 조건(다른 해 데이터만으로 예측).

모드20242025등급 적중
A in-sample (시간 분배 검증)0.240.2182% / 100%
B cross-year (2026 조건)0.420.4476% / 88%

수치 = |오차|합 ÷ 실측합. B 오차의 주원인은 연도 간 총량 이동(여의도(5) 21시 17.8천↔12.5천) — 예측 밴드가 이 폭을 표시한다. 그 외 pytest 불변식 21건(수요 보존·지연 합=1·통제 이월·스키마·회귀 가드) 상시 통과.

3.5 피더 선행지표 — 어디서 타고 오는가

  • KT OD·전 역 초과 승차로 출발역 역추적: 귀속 양수 221개 역, 상위 17개 역이 25% (신도림·영등포·당산·노량진·사당·고속터미널·홍대 등).
  • 사전 근거: 피더 귀속 승차(시각 h) vs 여의도 도착(h+1시간) 상관 r = 0.99 (2024·2025 공통). 원거리 역(성수·잠실, 소요 30분+)일수록 1시간 지연 상관이 우세 — 물리와 일치.
  • 당일 계획: 피더 핫스팟 12곳을 전용 API 키 2개로 5분 수집(9/4·9/5) → 9/6에 분 단위 선행 시간 검증. 9/5 모델 입력에는 쓰지 않는다(미검증 관측 차단) — 검증되면 "도착 30분 예측" 확장으로 제출.

3.6 CCTV 밀도 — 보행속도 보정

  • TOPIS 공개 CCTV 23대, 딥러닝 카운팅(DM-Count). 프레임은 저장하지 않고 집계만 기록.
  • 출구 주변 5대에 ROI 캘리브레이션 완료: 통제 시 보행로가 될 차도(여의동로·마포대교·원효대교·의사당대로)를 다각형으로 지정, 면적은 교량 공식 제원·OSM 차로수 기반 추정(±35%, 표기).
  • 밀도(명/m²) → Weidmann 보행속도 → 출구 도달 지연이 실측으로 움직인다. 캘리브레이션 안 된 카메라는 모델에서 자동 제외(화면 참고용).
