# Claude Design 핸드오프 — 불꽃축제 귀가 내비 (서울세계불꽃축제 2026)

작성 2026-08-29 · 이 폴더는 디자인 작업에 필요한 재료 전부다. 코드·데이터는 저장소 루트, 화면 디자인은 Claude Design에서.
방어 배점: 가공된 산출물 퀄리티 25 · 현업 적용 20. 심사 제출 = 웹페이지 링크(GitHub Pages) + 영상 3분.

## 1. 한 줄

**"지금 어디로 나가야 덜 막히나"** — 100만 명이 모이는 서울세계불꽃축제(㈜한화 주최) 관람객이 불꽃이 끝난 직후, 통신이 흔들리는 인파 속에서 한 손으로 보는 **귀가 출구 안내판**.

- 주최: 한화그룹 (2000년부터 사회공헌). 우리는 한화 **고객경험 혁신 TF**(과제 03 시나리오) 입장.
- 대상: 관람객 (2025 실적: 20·30대 여성 최다). 야간, 야외, 한 손, 배터리·통신 열악.
- 화면의 단 하나의 일: **출구 순위를 3초 안에 읽게 한다.** 나머지는 근거·상태·플랜.
- 왜 필요한가: 일반 지도앱은 당일 통제를 모른다 → 무정차 통과하는 **여의나루역**으로 안내한다. 서울시 실시간 도시데이터는 "붐빔" 상태만 주고 **행동(어디로·언제)** 은 주지 않는다.

## 4. 등급 색 (기능색 — 브랜드색과 분리)

서울시 실시간 도시데이터 4단계와 같은 의미 체계를 유지한다. 부하율 = 예상 수요 ÷ 시간당 처리량.

| 등급 | 조건 | 제안색 | 의미 |
|---|---|---|---|
| 여유 | < 0.5 | 초록/민트 계열 | 바로 가면 됨 |
| 주의 | 0.5~0.8 | 노랑 | 줄 생김 |
| 경계 | 0.8~1.0 | 주황 — **한화 오렌지와 구분되게** (채도·명도 다르게) | 이 시간대 안에 겨우 |
| 심각 / 무정차 | ≥ 1.0 / 통제 | 빨강 / 회색+빗금 | 다른 출구로 |

주의: 한화 오렌지를 "경계" 색으로 쓰면 브랜드 = 위험이 된다. 브랜드 오렌지는 상단·CTA에만, 등급 오렌지는 다른 톤으로.

## 6. 카피 (한국어, 그대로 사용 가능)

- 제목: `불꽃축제 귀가 내비` / 부제: `서울세계불꽃축제 2026 · 9/5(토) 여의도한강공원 · 관람객용`
- 보드 제목: `21시에 나가면 어디가 덜 막히나` / 설명: `역별 예상 부하율 = 예상 수요 ÷ 시간당 처리량. 1.0을 넘으면 그 시간대 안에 못 빠져나간다.`
- 무정차: `여의나루 · 20:40~21:40 통제 · 여의도역으로`
- 지도: `구역 → 출구` / `원 = 출구, 마름모 = 공개 CCTV, 점선 = 마포대교 임시 보행로. 좌표는 근사.`
- 플랜: `통신 끊겨도 쓰는 카드` / `출발 전에 이 페이지를 한 번 열면 마지막 데이터가 이 기기에 남는다.`
- 출구 설명 7개: 여의나루(5) `5호선 · 북행·동행` · 여의도(5) `5호선 · 서행(신길·영등포 방면)` · 여의도(9) `9호선 · 남·남동(동작·강남 방면)` · 샛강(9) `9호선 · 신림선 환승` · 국회의사당(9) `9호선 · 당산·김포 방면` · 신길(1·5) `1·5호선 · 도보 20분, 분산 출구` · 마포역 도보 `마포대교 보행로 25분 → 5호선 마포역`
- 방향 플랜(4장): `data/../docs/index.html`의 `PLANS` 상수에 전문.
- 출처 푸터: 서울 열린데이터광장 실시간 도시데이터 · KT 수도권 생활이동(OA-22300·22657) · 서울교통공사 승하차(OA-12921) · 서울 TOPIS CCTV · 서울시 인파 기준 3/4/5명/m²
- 톤: 평서문, 명령형 짧게, 사과·감탄 없음. 숫자는 항상 단위·기준시각과 함께.

## 9. 기술 제약 (디자인이 지켜야 하는 것)

- 정적 HTML 1장(GitHub Pages). 외부 의존은 Leaflet(지도) + Google Fonts 정도. 서버 없음.
- 5분마다 `data/latest.json` fetch. 실패 시 localStorage 마지막 값 표시.
- 모바일 우선(375px), 야간 야외 — 고대비, 큰 터치 타깃(≥44px), 한 손 스크롤. 다크 배경이 자연스럽지만 **한화 로고 규정(백색 배경 원칙)** 은 헤더 영역에서 지킬 것(흰 로고 반전 허용).
- 접근성: 등급을 색으로만 구분하지 않기(텍스트·아이콘 병기), 키보드 포커스, prefers-reduced-motion.
- 기능 프로토타입 `docs/index.html`(저장소)에 데이터 바인딩 로직이 있다. 디자인 결과물은 이 JS와 합쳐 쓴다 — 요소 id를 유지하거나 바인딩 표를 함께 넘겨주면 된다.
